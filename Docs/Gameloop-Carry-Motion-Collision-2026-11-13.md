# Heavy carry motion and collision — 13 November 2026

Subsequent placement repair and testing are documented in `Gameloop-Placement-Verification-2026-11-13.md`; the placement exclusion below describes the earlier carry-motion-only pass.

## Changes

- Cooperative velocity is sampled from completed Rigidbody displacement rather than commanded movement. Idle turning, an active orbiting operator and a stationary anchor now supply distinct movement to animation.
- Walking state supports the very slow solo-heavy speed, and the old minimum playback floor was removed. Backward playback and visible sideways stride direction apply to normal carried objects as well as the hose. Idle transitions still use unsmoothed movement.
- Cooperative translation/rotation uses one common permitted motion fraction for the object and both holders. Turning cannot move an operator faster than their loaded walking speed. Holders still turn toward their carrying orientation while idle.
- CarryMotionGuard checks the actual solid colliders attached to guarded bodies, translation sweeps and intermediate rotated poses in <=5 mm surface-travel steps. It filters self/holder/trigger collisions, preserves existing support contact, and backs away from newly blocked motion.
- Stable solo carry limits player translation and yaw together with the held object. The check follows the actual parent-pivot arc. If yaw is blocked, a safe straight retreat/slide remains possible. Object pose/reach corrections also respect the environment.
- Supported-edge lift checks follow the real pivot arc rather than a root-position chord that can dip into the floor. Cooperative release leveling is also limited by the surroundings.

No scene, prefab, animation clip, input-binding or camera configuration was saved by this change. Existing user changes were preserved. New helper/test .meta files are generated by Unity.
